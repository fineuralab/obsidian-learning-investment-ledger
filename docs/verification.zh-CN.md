## 记录完整性与日期回归

另增加 15 项回归测试，覆盖公开前发现的五项问题：

- 重命名的源文件支持合法 YAML 注释、带引号的属性名、显式字符串标签、行内映射及 BOM／CRLF。冷启动时，截断的属性区会提示具体文件；无关 Markdown 仍被排除。建立索引不修改源文件字节。
- 已删除投入项或先前数据文件夹的旧表单不能重新创建、复制记录；覆盖尚未完成重建索引及新目录存在相同 ID 副本的情况。正常新建仍可进行，失败操作保留源文件和输入。
- 保存及删除核对读取记录时的源快照，外部修改没有更新 YAML 时间戳时也会阻止旧操作；只修改注释的情形同样受保护。校验信息仅保留在内存中，不写入账本文件。
- 中英文的「本月」「近 30 天」随日期变化更新；刷新前直接导出 CSV 也使用当前范围，自定义日期保持固定。定时、窗口聚焦及页面可见性检查更新到期数量，视图卸载后释放相关资源。
- 将最近一次回访改到更早日期或仅调整时刻后，按新的最近一次回访重算提醒日期，必要时清空；修改旧历史或新增回溯记录仍保留手动设置的安排。
- 中英文过期删除确认框均保留后续新增事件并显示处理提示，重新查看、确认后才可删除。

另将当前安装 ZIP 载入独立 Obsidian 1.14.5 临时库实测：自定义文件名、带引号的 YAML 属性名与注释均正确读取；将最近回访前移后，提醒改为新的最近一次回访所安排的日期；外部新增事件且未改时间戳后，旧删除确认被阻止；编辑表单打开时移走源文件，保存被阻止且输入保留；截断文件显示具体文件名和 YAML 错误，正常记录继续显示；原生 CSV 导出的两笔交易、日期和总额与源记录一致。验收后恢复原测试目录设置。跨日期行为使用上方可控时钟测试，没有修改系统时间。

## 对应需求中的八项验收

| 验收项 | 实际核对 |
| --- | --- |
| 1. 支出与退款金额 | 用真实表单核对了原始需求中的金额用例；退款金额超过原支出 0.01 元时被拒绝，且输入保留 |
| 2. 事件、排序、筛选 | 五种事件进入时间线；切换顺序与原顺序完全相反；事件类型和关键词组合筛选正确 |
| 3. 投入项详情和链接 | 点击事件打开对应详情；成果文件通过 Obsidian 打开正确笔记；原生重命名后项目和成果路径更新 |
| 4. 编辑和删除同步更新 | 将工具支出增加 1 元，净支出同步增加 1 元，恢复后净支出同步恢复；确认删除学习记录后时间线同步移除；核心测试覆盖退款编辑与删除 |
| 5. 回访到期和历史 | 设置今天回访显示待回访 1；提交回访且不设下次日期后为 0；重载及完整退出后回访内容保留 |
| 6. 重启持久化 | 新建 store 从文件重建与原记录逐项相同；真实应用完整关闭、启动后金额、链接、回访均保留 |
| 7. 异常状态 | 空状态可主动载入演示；删目标保留并标记失效；模拟磁盘写入异常时保留快速输入；破坏 YAML 后显示具体源文件，修复后可重建 |
| 8. 导出一致性 | 真实 CSV 为四笔流水，日期、金额与表单一致，净影响合计与界面一致；复盘包含用户评价和对应链接 |

在原生重命名验收中发现并修复了 Obsidian 自动更新正文 wiki 链接、稍后写回旧属性的时序问题：插件只修复命中重命名前修订的旧路径，新用户修订继续作为权威。此情形已有独立回归测试。

## 复现

核心检查：

```sh
npm ci
npm test
npm run build
```

真实应用检查需要本机 Obsidian 和安装了 Playwright 的 Python。下面的路径专用于隔离验收：

```sh
node scripts/setup-test-vault.mjs
```

准备命令会输出当前操作者的临时测试库和配置目录。使用输出的配置位置启动 Obsidian，指定 `--user-data-dir`、`--remote-debugging-port=9225` 和 `--no-first-run`，然后执行：

```sh
python scripts/ui_acceptance.py --reset
```

脚本先核对活动库路径，只对独立验收库执行写入；`--reset` 会把该测试库内前一轮文件移入它自己的回收站。关闭独立应用再用相同参数启动，运行 `python scripts/ui_acceptance.py --restart-check` 核对恢复。`python scripts/capture-ui.py` 保存真实截图。
